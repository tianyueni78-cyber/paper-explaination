# 创新想法1：预测—优化式搜索容量规划

## 一、想法

将候选评价次数视为有限计算容量。使用历史状态—动作数据分别预测不同复合动作的质量收益和运行时间，再在响应时间上限内选择预计收益最高的动作。

候选动作沿用已有探针中的`Top-K区域规模×候选评价预算`。该想法原计划训练数据分析、特征工程、回归预测、预测误差评价、容量规划和成本—收益决策等可迁移就业能力。

## 二、本次探针做了什么

- 数据来源：原E06多状态Oracle探针产生的状态—动作记录；
- 状态数量：6个机器故障状态，覆盖3个事件时刻和2个故障机器目标；
- 动作：Top-5/Top-10与10/50/200次评价预算组合；
- 预测目标：支配改善率和墙钟时间；
- 模型：随机森林预测改善率，线性回归预测耗时；
- 数据划分：按事件阶段进行三折留出，每次使用另外两个阶段训练、完整留出一个阶段测试；
- 决策：在由训练数据确定的响应时间上限内选择预测改善率最高的动作；
- 对照：训练集最佳固定动作和测试状态Oracle。

## 三、实验结果

| 指标 | 结果 |
|---|---:|
| 测试状态 | 6 |
| 预测策略平均改善率 | 0.3627 |
| 最佳固定策略平均改善率 | 0.3627 |
| Oracle平均改善率 | 0.3627 |
| 预测策略战胜固定策略 | 0/6 |
| Go/Stop | Stop |

早期和中期状态下，预测策略、固定策略和Oracle均选择`K5_B50`。晚期状态下，预测策略选择较短的`K5_B10`，但该阶段几乎所有短预算动作的支配改善率均为0，因此减少计算没有带来质量增量。

## 四、为什么暂时否决

当前数据中，预测策略没有在任何测试状态下优于最佳固定策略，也没有提高平均改善率。继续加入监督学习只会增加模型、参数、训练和消融成本，尚无证据表明它能增强算法效果或论文创新强度。

因此，该想法不进入当前冻结创新方案，不修改`Python-NEW`，也不覆盖原`innovation_probe`。

## 五、证据边界

本次Stop只适用于当前数据和动作集合，不能证明预测—优化方法在所有动态调度场景中无效。当前探针只有机器故障、3个事件阶段和有限动作；两个故障机器目标产生的动作表现也高度相似，状态差异不足。

只有未来获得订单取消、机器故障、AGV故障、多严重程度及更丰富邻域动作的数据，并且不同状态确实呈现不同最优搜索投入时，才值得重新启动该方向。
