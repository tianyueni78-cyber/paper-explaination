# A3-4 算法表达与伪代码

> 2026-08-31复核：第11–13节的完备性判断仅为旧版记录，不能用于当前A3验收。新增第14节与A3-3第12节为配套待批准草案；尚未修改v1.3及算法代码。

## 1. 一句话定位

本算法保留冻结baseline的动态事件、状态继承和解码评价，但不假定三类动态活动路径原本都运行Q-learning。它把原静态核心中的Q-learning/N1–N6作为拟验证控制机制接入独立创新算法，并进一步联合选择搜索区域规模、当前合法邻域和候选评价数量；候选仍由原动态解码器评价。

## 2. 保持不变与新增内容

| 类别 | 内容 |
|---|---|
| 保持不变 | 问题数据、染色体、动态事件、fixed/residual继承规则、解码器、两个目标字段、NSGA-II选择交叉变异排序与精英保留 |
| 保留并扩展 | Q-learning、N1–N6局部邻域 |
| 新增 | 动作掩码、资源瓶颈诊断、Top-5/Top-10区域、10/50/200评价预算、质量—成本奖励、并行候选解码 |
| 第一版不做 | 数学求解器精确修复、PPO/DQN、预测模型、新目标、新数据和新业务场景 |

### 2.1 前身、D2NSGA-II与本文的算法层次对照

| 对照层次 | 前身QNSGA-II | D2NSGA-II | 本文v1.3 |
|---|---|---|---|
| 问题场景 | 动态机器–AGV协同调度，包含三类事件 | 静态异构AGV柔性作业车间 | 继承前身动态场景，不改问题模型 |
| 全局框架 | NSGA-II | NSGA-II | 保持前身NSGA-II主体不变 |
| 局部算子 | N1–N6 | 基于关键路径/关键块设计的N1–N6 | 保留前身N1–N6，增加区域限制和动作掩码 |
| 学习器职责 | 静态核心由Q-learning选择邻域；动态活动路径未在三类事件中统一启用 | Double DQN依据13维状态选择邻域类型 | 将Q-learning接入三类动态事件，并在合法动作中联合选择邻域、Top-K规模和评价预算 |
| 搜索位置 | 未显式生成事件后瓶颈Top-K区域 | 关键路径和关键加工/运输块 | fixed/residual边界内的事件后机器或AGV瓶颈Top-K区域 |
| 计算投入 | 固定算法预算 | 算法间使用相同CPU时间 | 评价预算是复合动作维度；总预算由实验协议限制 |
| 奖励 | 原Q-learning奖励 | 支配或互不支配时奖励10 | 共同尺度下的Pareto质量增量减去预算成本和不可行惩罚 |
| 评价方式 | 串行完整解码 | 未报告候选并行解码 | 候选固定后并行调用原动态解码器，Q更新与环境选择保持串行 |

该表说明本文不是用新算法替换QNSGA-II，也不是把D2NSGA-II移植到动态场景。本文保留前身问题和解码框架，但“在三类动态事件中统一运行Q-learning”本身就是新增接入行为。若导师同意该路线，A5正式比较协议应增加独立动态接入消融，把该收益与Top-K、预算复合动作和新奖励的收益区分开；在导师确认前不改写v1.3消融编号。

| 模块 | 输入 | 输出 | 职责 |
|---|---|---|---|

## 5. 总算法伪代码

```text
算法1：瓶颈感知的预算自适应QNSGA-II动态局部搜索

输入：当前种群P，动态事件e，重调度策略policy，评价总预算B_total，Q表
输出：下一代种群P_next，更新后的Q表，搜索记录log

1. 调用冻结baseline分析动态事件，得到fixed、residual和资源继承状态
2. 调用冻结baseline确定当前可修改染色体片段
3. 使用当前代表解的完整解码结果计算机器与AGV剩余负载
4. 根据可修改片段确定当前能够作用的资源类型
5. 对每种可作用资源生成按贡献排序的残余工序列表
6. 根据事件类型、事件阶段、可重调比例、瓶颈类型、瓶颈严重度、停滞和剩余预算组成状态s
7. 枚举邻域、区域规模和评价预算的全部复合动作
8. 删除违反动态边界、区域为空或超过剩余预算的动作
9. 使用原Q-learning探索规则从合法动作中选择动作a
10. 从动作a读取邻域n、区域规模K和评价预算b
11. 取得对应瓶颈贡献列表的前K道工序，形成局部区域R
12. 在R内重复执行受限邻域n，生成b个带固定编号的候选染色体
13. 并行调用冻结动态解码器评价全部候选
14. 主进程按候选编号恢复结果顺序并剔除不可行候选
15. 将可行候选加入临时非支配档案，计算动作前后的归一化HV
16. 根据HV增量、实际解码次数和不可行率计算奖励
17. 串行更新Q表
18. 将候选与当前种群合并，调用原NSGA-II环境选择得到P_next
19. 保存状态、动作、区域、预算、目标、奖励和墙钟时间到log
20. 返回P_next、Q表和log
```

## 6. 合法动作生成伪代码

```text
算法2：生成当前动态状态的合法复合动作

输入：事件e，策略policy，可修改片段M，候选区域集合Regions，剩余预算B_rem
输出：合法动作集合A_legal

1. 初始化A_legal为空集合
2. 依次检查N1–N6
3. 如果邻域修改的染色体片段不属于M，则跳过该邻域
4. 如果邻域是N3或N4，确认当前策略为CS，或当前为机器故障RS且目标工序原计划位于故障机器、开始时间不早于事件时刻
5. 对K等于5和10分别检查对应区域是否非空
6. 对b等于10、50和200分别检查b是否不超过B_rem
7. 如果片段、工序、资源可选集、故障区间、区域和预算检查全部通过，则加入动作（邻域，K，b）
8. 返回A_legal
```

## 7. 瓶颈Top-K区域伪代码

```text
算法3：生成瓶颈Top-K残余工序区域

输入：完整解码结果schedule，可重调集合residual，可作用资源类型resource_type，区域规模K
输出：瓶颈资源bottleneck，严重度severity，局部区域R

1. 如果resource_type为机器，则计算每台可作用机器的剩余加工时间总和
2. 如果resource_type为AGV，则计算每辆可作用AGV的剩余空载、负载和运输等待时间总和
3. 选择同类剩余负载最大的资源作为bottleneck
4. 用瓶颈负载除以同类资源平均正负载，得到severity
5. 从residual中筛选与bottleneck相关且当前允许修改的工序
6. 计算每道工序对瓶颈剩余负载的贡献
7. 按贡献从高到低排序；贡献相同时按工序全局索引排序，保证可复现
8. 取前K道工序；不足K道时取全部合法工序
9. 返回bottleneck、severity和R
```

## 8. 并行候选评价伪代码

```text
算法4：保持结果一致的并行候选评价

输入：带编号候选集合C，冻结数据data，动态状态dynamic_state，进程数workers
输出：按编号排列的评价结果E

1. 主进程在并行开始前固定所有候选及其编号
2. 每个工作进程只读取data、dynamic_state和一个候选染色体
3. 工作进程调用同一个冻结动态解码器
4. 工作进程返回候选编号、可行性、目标1、目标2和解码耗时
5. 主进程等待全部任务结束
6. 主进程按候选编号排序，恢复与串行评价相同的顺序
7. 检查候选数量、可行性和目标结果是否完整
8. 返回E
```

## 9. 与原算法的插入位置

原NSGA-II仍完成初始化、交叉、变异和环境选择。原Q-learning局部搜索开始前增加动态合法范围提取和瓶颈区域生成；原来只包含邻域编号的动作扩展为邻域、区域规模和评价预算；局部邻域仍使用N1–N6，但只能修改选定区域；候选生成后增加并行解码；所有候选返回后，再沿用主流程串行计算奖励、更新Q表并执行环境选择。

## 10. 主要计算开销

设残余工序数为`R`，资源数为`m+v`，候选数为`b`，一次完整动态解码成本为`D`。

- 瓶颈统计需要遍历现有机器和AGV时间表，开销与调度块数量近似线性相关。
- 工序贡献排序的上界为`O(R log R)`。
- 候选生成开销约为`O(bK)`，通常小于完整解码开销。
- 串行候选评价主要开销约为`O(bD)`。
- 使用`w`个进程时，理想解码时间约为`O(bD/w)`，实际还包含进程启动、数据传输和结果排序开销。
- Q表查询和更新相对于完整解码属于小开销，但36个理论动作可能造成状态–动作访问稀疏，需要由Oracle实验验证是否值得保留。

```text
每次独立的实例—事件—种子运行：Q清零，停滞代数h=0
每代：
    按冻结主体完成交叉、变异、第一次环境选择，得到P
    queue = 按冻结遍历顺序排列的P快照（本阶段不修改）
    Archive = ND(P); accepted = []; B_rem = B_total; improved = false
    寻找queue中第一个有合法复合动作的父解
    while 存在当前父解：
        统计负载，按A3-3草案选一个资源
        按邻域权限生成各Top-K区域，屏蔽非法动作和b>B_rem
        s = 当前父解七字段状态（使用当前预算及停滞标记）
        a = 在合法集合内按继承的选择概率函数查询Q
        C = 从同一父解分别生成b个受限候选，主进程固定编号
        E = 按编号收齐解码结果；基础设施异常则退出并标记异常运行
        B_rem -= 实际完成数量（包括返回不可行的评价）
        按原相对父解的接受判据收集候选，更新Archive
        以动作前后档案计算原奖励；若改善则improved=true
        寻找下一有合法动作的队列父解（用更新后的预算与状态）
        如存在：next_value = max Q(s_next, 下一合法动作)
        否则：next_value = 0
        Q(s,a) += alpha * (reward + gamma*next_value - Q(s,a))
        前进到下一父解；不把本批最佳候选作为下一父解
    P = 原环境选择(P ∪ accepted)
    h = 0 if improved else h+1
    下一代保留Q；终止整次运行仍遵守A5正式停止协议
```

### 14.1 复述例子（仅示意，不是实验结果）

父解队列为`p1,p2,p3`，阶段预算为100。p1选择`(N5,Top-5,50)`，50个候选都从p1生成；完成后预算50，下一状态来自p2而非p1的最佳候选。如果p2也选择50并完成，预算为0，后继价值为0，p3本阶段不再搜索。两批完成后统一环境选择；下一代Q仍保留，新独立种子才清零。

若p2没有合法动作，应跳过它检查p3；若都没有，则立即终止阶段。不得凭空修改权限以消耗完预算。
