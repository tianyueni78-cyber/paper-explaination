# A3-3 正式算法定义

## 1. 适用边界

本算法以`baseline-matlab-observed-v1.0`为固定调用方。问题数据、染色体、动态事件、解码器、两个目标字段和NSGA-II主体均保持一致。创新算法不得反向修改该标签。

第一版不调用数学求解器，不引入PPO、DQN或预测模型。N1–N6继续作为候选染色体的修改算子；Q-learning负责选择局部搜索方式与计算投入；并行模块只负责候选解码。

## 2. 基本对象与符号

| 符号 | 定义 |
|---|---|
| `P` | 当前NSGA-II种群 |
| `e` | 当前动态事件及其类型、发生时刻、资源和持续时间 |
| `fixed` | 事件后不可修改的工序集合 |
| `residual` | 事件后允许重新调度的工序集合 |
| `M(e)` | 当前重调度策略允许修改的染色体片段 |
| `A_legal` | 当前状态下通过动作掩码的复合动作集合 |
| `K` | 局部区域规模，第一版取5或10 |
| `b` | 候选完整解码次数，第一版取10、50或200 |
| `B_total` | 一次局部搜索阶段允许的总解码预算 |
| `B_rem` | 当前剩余解码预算 |
| `Archive` | 当前非支配解档案 |

## 3. 三类事件的状态字段

| 状态字段 | 取值或计算方法 | 作用 |
|---|---|---|
| 事件类型 | 订单取消、机器故障、AGV故障 | 区分扰动来源 |
| 事件阶段 | `t_event / Cmax_before`小于等于1/3为早期，大于1/3且小于等于2/3为中期，其余为晚期 | 表示剩余计划长度 |
| 可重调比例 | `|residual| / 总工序数`，按校准状态集的33%和67%分位点分为小、中、大 | 表示事件影响范围 |
| 瓶颈类型 | 机器瓶颈或AGV瓶颈；只在当前合法动作能够作用的资源类型中产生 | 保证诊断与动作匹配 |
| 瓶颈严重度 | 瓶颈资源负载除以同类资源平均正负载，按校准集33%和67%分位点离散 | 表示资源失衡程度 |
| 搜索停滞 | 距离非支配档案上次改善的代数除以停滞上限`H`，按1/3和2/3分为短、中、长 | 表示继续加大搜索的必要性 |
| 剩余预算 | `B_rem / B_total`，按1/3和2/3分为低、中、高 | 防止动作超出剩余计算资源 |

Q表状态由上述离散字段组成。第一版不把AGV电量作为状态字段，因为baseline活动路径允许出现充电前暂时负电量，该数值的物理解释尚未完全关闭。

## 4. 合法动作空间

N1和N2修改OS，N3和N4修改MS，N5和N6修改AS。第一版不新增VS邻域。

| 事件与策略 | 合法邻域原则 |
|---|---|
| 订单取消RS | baseline返回`OS、AS、VS`；N1、N2、N5、N6可在`residual`内使用，MS继承原染色体，因此屏蔽N3、N4 |
| 机器故障RS | baseline返回`OS、MS_FAULT_ONLY、AS、VS`；N3、N4只能修改原计划中位于故障机器、且开始时间不早于事件时刻的残余工序MS位置 |
| AGV故障RS | baseline返回`OS、AS、VS`；N1、N2、N5、N6可在`residual`内使用，MS继承原染色体，因此屏蔽N3、N4 |
| CS | 在满足工序优先关系、机器可选集和资源状态约束的前提下允许N1–N6 |

上述边界来自冻结baseline的`build_rescheduling_plan`与`_constrain_chromosome`活动调用路径，并由Gate 6的10项动态重调度测试复核通过。IS不执行优化，返回空可修改片段。

### 4.1 三类事件的N1–N6合法动作表

| 策略与事件 | N1/N2：OS | N3/N4：MS | N5/N6：AS |
|---|---|---|---|
| IS，任意事件 | 禁止 | 禁止 | 禁止 |
| RS，订单取消 | 允许，仅限`residual`区域 | 禁止 | 允许，仅限`residual`区域 |
| RS，机器故障 | 允许，仅限`residual`区域 | 条件允许：仅限原计划位于故障机器且开始时间不早于事件时刻的残余工序 | 允许，仅限`residual`区域 |
| RS，AGV故障 | 允许，仅限`residual`区域 | 禁止 | 允许，仅限`residual`区域 |
| CS，任意事件 | 允许 | 允许 | 允许 |

表中的“允许”仍需同时满足区域非空、邻域所需工序数量充分、机器或AGV候选集合法、故障区间不可用约束和剩余预算充足。任何一项不满足时，动作掩码删除该复合动作。

动作掩码不根据经验硬编码“哪个动作更好”，只检查四件事：算子修改的片段是否属于`M(e)`，算子涉及的工序是否属于当前区域，资源选择是否满足可选集与故障区间约束，所需评价预算是否不超过`B_rem`。

复合动作定义为：

```text
a =（邻域类型n，区域规模K，候选评价预算b）
n属于当前合法的N1–N6子集
K属于{5, 10}
b属于{10, 50, 200}且b不超过B_rem
```

理论动作上限为36个，动作掩码会根据事件、策略、区域和剩余预算删除不可执行动作。

## 5. 瓶颈指标与Top-K贡献

### 5.1 机器剩余加工负载

对机器`m`，事件后的剩余加工负载定义为：

```text
L_machine(m) = residual中当前分配给机器m的各工序剩余加工时间之和
```

机器瓶颈为具有最大`L_machine`的、且当前合法动作可以影响的机器。机器严重度为该最大负载除以所有正机器负载的平均值。

工序`o`对机器瓶颈的贡献定义为其在瓶颈机器上的剩余加工时间。只有属于`residual`且当前位于瓶颈机器上的工序参加排序。

### 5.2 AGV剩余运输负载

对AGV `v`，事件后的剩余运输负载定义为：

```text
L_agv(v) = residual相关的剩余空载行驶时间、负载行驶时间和运输等待时间之和
```

AGV瓶颈为具有最大`L_agv`的、且当前合法动作可以影响的AGV。AGV严重度为该最大负载除以所有正AGV负载的平均值。

工序`o`对AGV瓶颈的贡献定义为该工序在瓶颈AGV时间表中对应的剩余空载、负载和运输等待时间之和。只有属于`residual`且与该AGV运输任务相关的工序参加排序。

### 5.3 区域生成

机器和AGV分别在同类资源内部比较，不直接把加工时间与运输时间混为一个总分。算法先根据当前合法邻域确定可作用的资源类型，再为每个可作用类型生成候选区域。各区域按工序贡献从高到低排列，取前`K`道形成Top-K区域；不足`K`道时使用全部合法工序。

## 6. 区域与预算档位

第一版区域档位固定为Top-5和Top-10，依据E02在相同50次评价下的探针结果保留。第一版候选评价预算固定为10、50和200次，依据E03覆盖短、中、长三档搜索投入。

这些数值是v1.3实验规格，不宣称对所有实例最优。正式实验不得在看到结果后临时改档位；如需调整，应建立新规格并重新登记实验。

## 7. 奖励结构

设动作执行前后的非支配档案超体积分别为`HV_before`和`HV_after`。HV使用正式实验预先固定的归一化范围与参考点。

```text
quality_gain = (HV_after - HV_before) / max(abs(HV_before), epsilon)
budget_cost = 实际完成的候选解码次数 / B_total
infeasible_rate = 不可行候选数 / 实际完成的候选数
reward = lambda_q × quality_gain
         - lambda_b × budget_cost
         - lambda_f × infeasible_rate
```

其中`epsilon`取`1e-12`。`lambda_q`、`lambda_b`和`lambda_f`为非负奖励权重，由A5参数协议冻结。若动作因剩余预算不足或合法区域为空而不能执行，则不调用解码器，奖励记为`-1`。

### 7.1 奖励可计算性检查

| 奖励量 | 数据来源 | 当前判断 | 正式实现约束 |
|---|---|---|---|
| `HV_before`、`HV_after` | 动作前后非支配档案的Makespan与TEC | 可计算；baseline已有二维HV实现 | 两者必须使用A5预先冻结的同一归一化上下界和参考点，禁止分别重算min–max范围 |
| 实际完成的候选解码次数 | 候选评价返回记录 | 可直接计算；现有探针已记录 | 超时或异常候选也必须有明确完成状态，不能用计划候选数代替 |
| 不可行候选数 | 解码异常、约束验证或可行性标志 | 可直接计算；现有探针已记录 | 不可行判定规则必须与冻结解码器及动态验证器一致 |
| 墙钟时间 | 主进程计时 | 可计算 | 只用于效率报告和并行加速比，不进入第一版Q表奖励 |

如果动作前档案HV为0，分母使用`epsilon`避免除零；该情况下奖励尺度是否过大由A5试运行检查，不能在正式结果产生后临时修改公式。

奖励使用解码次数而不是墙钟时间作为主要成本，是为了减少硬件和进程启动开销对Q表学习的污染。墙钟时间单独记录，用于动态响应效率和并行加速评价。

Q表仍使用原Q-learning更新形式，不改为深度强化学习：

```text
Q(s,a) = Q(s,a) + alpha × [reward + gamma × max Q(s_next, a_next) - Q(s,a)]
```

`alpha`、`gamma`和探索规则首先继承冻结baseline；若正式实验需要改变，必须登记为新的算法差异。

## 8. 并行评价边界

候选染色体生成完成后，为每个候选分配固定编号。多个工作进程只读取同一数据、事件状态和解码器并返回编号、可行性及两个目标。主进程按照编号恢复顺序，再计算奖励、更新Q表、合并种群并执行NSGA-II环境选择。

并行评价不得在工作进程中修改Q表、随机数主状态或种群，从而保证1、2、4进程得到相同候选和目标结果。

## 9. Q-learning保留条件

Q-learning是拟实现控制器，不是已被实验确认的必要模块。多事件Oracle必须至少发现两个状态具有不同的最优复合动作集合，才支持“状态自适应选择”的主张。如果正式Oracle仍显示一个固定动作普遍最优，则完整方法收缩为瓶颈区域加预算规则控制器，Q-learning只作为未获支持的消融版本报告。

## 10. A3固定结构与A5待定参数

| A3已经固定 | A5必须在正式实验前冻结 |
|---|---|
| 七类状态字段及其计算含义 | 状态离散化使用的校准样本、33%/67%分位点具体数值和停滞上限`H` |
| 复合动作由邻域、区域规模和评价预算组成 | 是否保留全部`K={5,10}`与`b={10,50,200}`档位，以及总预算`B_total` |
| 奖励包含质量增量、预算成本和不可行惩罚 | HV归一化上下界、参考点、`lambda_q`、`lambda_b`、`lambda_f` |
| Q更新形式继承baseline | `alpha`、`gamma`、探索率及其衰减设置是否完全继承baseline |
| 候选并行解码，Q更新和环境选择串行 | 正式硬件、1/2/4进程配置、启动方式和计时范围 |

A3不得根据探针结果宣称上述数值对所有实例最优；A5必须先形成参数协议，再运行正式比较。

## 11. 可实现性语言检查

本定义中的事件阶段、可重调比例、瓶颈严重度、停滞和剩余预算均具有公式或离散边界。“严重度”是已定义变量名，不是主观程度词。文中不使用“适当区域”“较大预算”“严重故障”等无法直接转换为条件判断的表述；尚未给出具体数值的参数统一列入第10节，由A5冻结。
