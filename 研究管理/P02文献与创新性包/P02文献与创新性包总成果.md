# P02文献与创新性包总成果

## 一、结论先行

### 1. 文献核查得出的总判断

现有证据支持继续研究`(K,N,b)`，但**目前不能直接宣布它已经构成被充分证明的算法创新**。

原因不是“没有找到同名论文”，而是文献呈现出以下结构：

1. **选择局部搜索区域已有近邻思想。** 关键路径、关键工序、区域划分和专用邻域都在既有研究中出现，因此“只搜索重点区域”本身不是足够的新颖性来源。
2. **用Q-learning选择邻域已有直接先例。** 原始QNSGA-II已经在N1–N6中选择邻域，L005也使用Q-learning选择N1–N5，因此“Q-learning选择邻域”不能作为本文的新贡献。
3. **自适应调整局部搜索预算已有直接先例。** L116已经明确研究自适应分配局部搜索计算预算，因此“预算自适应”本身也不能单独作为创新。
4. **尚未发现与本文完全等价的直接近邻证据。** 当前核验材料中，没有确认某项工作同时基于机器–AGV排程反馈，联合决定局部区域规模K、邻域N和真实完整解码预算b，并在统一真实解码预算下验证三者的独立增量。
5. **第4点不是“创新成立”的证明。** 它只说明目前存在一个可继续核验和实验验证的组合机制空位；最终表述必须经过最近邻全文对比和消融实验。

### 2. 本文当前最稳妥的定位

本文不应写成：

> 首次使用Top-K、Q-learning或搜索预算解决机器–AGV调度问题。

当前可以使用的候选定位是：

> 面向静态机器–AGV协同调度，在保持原问题模型、解码器和NSGA-II主流程不变的条件下，研究一种由机器–AGV排程反馈驱动的局部搜索资源联合分配机制，使学习器在统一真实完整解码预算内共同选择局部区域规模K、邻域N和搜索预算b。

这一定义把拟议增量放在**三类搜索决策的联合控制、排程反馈和真实解码预算约束**上，而不是把三个已有概念分别包装成创新。

### 3. 对后续研究路线的直接决定

| 决定 | 结论 |
|---|---|
| 是否继续`(K,N,b)`路线 | 继续，但保持“候选方法”身份，未经过实验前不写成已证实贡献 |
| Top-K是否能单独作为创新 | 不能；必须强调机器与AGV排程反馈如何定义区域，并做无区域/固定K对照 |
| Q-learning选邻域是否能单独作为创新 | 不能；原始QNSGA-II和相关研究已有直接先例 |
| 预算b是否能单独作为创新 | 不能；已有自适应局部搜索预算研究，本文必须落实为真实完整解码计费 |
| 真正需要验证的组合 | 排程反馈＋K/N/b联合动作＋等真实解码预算＋机制诊断 |
| 必须保留的对照 | 原始仅选N、随机`(K,N,b)`、固定最佳`(K,N,b)`、完整联合学习及离线事后参考 |
| 论文能否声称算法优越 | 不能；现阶段只有文献定位，没有本文新方法的正式实验结果 |
| 文献之间能否直接数值排名 | 不能；实例、目标、预算、重复和参考前沿口径不一致，主要支持定性机制比较 |

## P02-06｜Top-K局部搜索相关研究给出了什么结论？

### 答案

## P02-08｜搜索预算分配研究给出了什么结论？

### 答案

29篇N6抽取显示，多数调度研究采用固定代数、固定时间或回合停止，不同论文的预算口径通常不可直接比较。L116明确研究自适应局部搜索计算预算，证明“自适应预算”已有先例。

## P02-09｜强化学习超启发式研究给出了什么结论？

### 答案

相关研究普遍由上层学习器根据状态或历史反馈选择低层启发式或算子，再依据执行后的质量变化更新策略。不同研究的主要差异是状态粒度、动作是否组合、奖励时间尺度以及预算是否进入动作。

### 结论

`(K,N,b)`的风险与潜在价值来自联合动作：它可能同时配置“在哪里搜、怎么搜、搜多少”，也可能因36动作过大而学不到稳定策略。因此必须与原始只选N、随机三元动作和固定最佳三元配置进行同预算比较。

### 证据

[六专题综合第9节](P02_95篇候选分层与六专题综合.md#9-p02-09强化学习超启发式相关研究)。

### 判定

通过。

## 三、已经回答与仍未回答的边界

### 已经回答

- 为什么该研究问题值得继续：原方法只选择N，没有联合控制K和真实解码预算b。
- 哪些思想已有先例：关键区域、Q-learning选邻域和自适应预算均已有先例。
- 当前最可能的机制差异：机器–AGV排程反馈下联合选择`(K,N,b)`。
- 后续实验必须回答什么：联合动作是否优于原始、随机和固定配置，收益是否在真实解码和墙钟成本下成立。

### 仍未回答

- 本文方法是否有效、是否稳定、是否值得增加复杂度；
- 最近强邻能否获得代码并在六维统一协议下运行；
- K/N/b、奖励和Q表的最终可执行定义。
