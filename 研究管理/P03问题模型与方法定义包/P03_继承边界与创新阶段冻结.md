# P03 原论文继承边界与创新阶段冻结

## 一、结论先行

本研究的创新范围正式固定为：

> **只改造原QNSGA-II的局部搜索资源分配与学习控制阶段：在N1–N6执行前，根据当前静态机器–AGV排程反馈构造Top-K候选区域，并由Q-learning联合选择`(K,N,b)`，其中K控制修改范围、N控制邻域类型、b控制本次允许消耗的真实完整解码次数。**

问题模型、目标函数、OS–MS–AS染色体、混合初始化、完整解码、遗传操作和NSGA-II多目标环境选择不属于创新范围。它们应作为共同算法底座保持一致；若论文、MATLAB与Python口径存在差异，先由A2确定baseline身份，不能借创新名义静默修改。

这意味着：**解码流程和遗传操作原则上不是“不可以用”，而是必须继承且不改行为。** 当前尚不能写“已经完全可直接使用”，只是因为A2的实现一致性与TEC口径仍需验收，而不是因为它们属于创新。

## 二、创新发生在哪一步

```text
共同底座（不创新）
输入实例
→ OS–MS–AS编码与混合初始化
→ 完整解码并计算makespan、TEC
→ NSGA-II选择、交叉、变异、评价和环境选择

创新阶段（唯一允许扩展的核心区）
→ 读取当前完整机器–AGV排程反馈
→ 分别计算机器瓶颈与AGV瓶颈
→ 将相关工序排序并构造Top-K合法修改区域
→ 构造受剩余预算约束的合法(K,N,b)动作
→ Q-learning选择(K,N,b)
→ 在Top-K区域内按N1–N6原始语义生成候选
→ 每个候选仍执行完整解码，每次真实解码立即扣减预算
→ 根据质量变化、成本和不可行情况计算奖励并更新Q表

共同底座（不创新）
→ 按既定接受/档案规则返回种群或Pareto档案
→ 达到统一停止条件后输出结果
```

创新入口：已有完整排程的当前解进入局部搜索之前。

创新出口：完成受预算约束的候选生成、完整评价、接受处理和Q表更新之后。

## 三、23项能否直接使用

| 内容 | 能否直接沿用原论文 | 本研究处理决定 | 原因/边界 |
|---|---|---|---|
| 符号表 | 不能整表照搬 | 静态符号选择性继承，并新增K、N、b、状态、预算和计数符号 | 原论文含动态事件与重调度符号；当前研究只做静态问题 |
| 问题假设 | 不能整段照搬 | 继承静态机器–AGV假设，删除订单取消、机器故障、AGV故障与重调度假设 | 防止动态范围重新进入本文 |
| 决策变量 | 静态部分可继承 | 机器选择、工序顺序、AGV分配与运输时序不变；新增算法控制量K、N、b，但它们不是调度模型决策变量 | 区分问题模型变量与算法控制动作 |
| 约束条件 | 静态部分可继承 | 继承工序优先、机器资格、机器/AGV容量、运输、位置、电量和充电约束；删除动态事件约束 | 不新增原模型没有的交通冲突等约束 |
| Makespan定义 | 原则上继承 | 数学含义不改；A2核对论文、MATLAB与Python计算路径后冻结 | 目标行为必须在所有比较算法中一致 |
| TEC定义 | 现在不能直接宣称已可用 | 保留原论文`TEC=E_busy+E_idle`候选口径，先关闭论文—MATLAB—Python目标组成冲突 | AGV电池约束不等于AGV能耗必然计入TEC |
| 染色体表示 | 原则上直接继承 | OS–MS–AS三段表示不改 | 新方法不改变解空间表示 |
| 初始化方法 | 原则上直接继承 | 原混合初始化保持一致 | 防止把初始化差异误算成局部搜索增量 |
| 解码流程 | 必须继承，不属于创新 | 每个新候选仍走同一完整解码；不得只解码Top-K局部 | Top-K限制修改范围，不改变可行性与目标计算 |
| 遗传操作 | 必须继承，不属于创新 | 选择、交叉、变异的基线语义和参数保持一致 | 新旧算法公平比较需要共同主循环 |
| 多目标选择 | 必须继承，不属于创新 | 非支配排序、拥挤距离、精英保留和档案规则不改 | 不把多目标选择变化混入创新效果 |
| N1–N6定义 | 原始语义继承，执行边界重写 | 六个邻域“怎样修改”的基本含义不改；新增“只能触碰Top-K合法区域”和无可执行动作处理 | 创新改变修改对象和投入，不偷换邻域本身 |
| 状态空间 | 新方法不能直接沿用 | A0保留原四状态；新方法重新定义静态瓶颈、停滞和剩余预算信息 | 原四目标象限状态未表达K和b决策需要的信息 |
| 动作空间 | 必须重写 | A0为N1–N6；新方法为合法`(K,N,b)`组合及动作掩码 | 这是创新控制接口的核心变化 |
| 奖励函数 | 必须重写并保留原版对照 | A0保留原奖励；新奖励必须同时防止质量尺度偏置和大b尝试机会偏置 | 直接复用原奖励可能系统偏好大预算 |
| 探索与利用策略 | 不能无条件照搬 | A0复现原策略；新方法需固定ε方向、衰减、并列动作和随机分支 | 当前论文表述与活动实现存在探索/利用方向差异 |
| Q表初始化、更新和生命周期 | 必须重新明确 | 写明表形状、初值、更新时点、跨代持续、独立运行重置及是否允许跨实例共享 | 36动作增加访问稀疏和信息泄漏风险 |
| 预算定义及真实扣减规则 | 必须新写 | 每次真实完整解码立即计费；区分生成、唯一、解码、接受数；邻域内部解码也计费 | 原论文主要按CPU时间比较，没有三元动作b语义 |
| 完整算法伪代码 | 必须重写 | 以共同底座包围唯一创新阶段，同时给A0/A1/A2/A3分支 | 原论文伪代码没有Top-K与b控制 |
| 输入与输出 | 必须扩展 | 输入新增K集合、b集合、预算、状态与奖励参数；输出新增动作、Q表、解码计数和诊断日志 | 新机制需要可审计信息 |
| 算法复杂度 | 必须重算 | 基于原主循环，加上瓶颈排序、合法动作构造、最多b次邻域生成和完整解码成本 | 不能直接引用原算法复杂度代表新方法 |
| 可逐步复述的小案例 | 必须新写 | 用静态小实例逐步展示排程反馈、Top-K、动作选择、候选完整解码、扣费、奖励和Q更新 | 原论文案例不能展示新增联合决策 |
| 原方法、新方法和消融差异表 | 必须新写 | 固定A0、A1、A2、A3和AO，仅允许K/N/b选择方式变化 | 用于隔离每个新增机制的实际增量 |

## 四、三类最终归纳

### A. 共同底座：应保持不变

- 静态问题模型与静态约束；
- makespan与最终冻结的TEC口径；
- OS–MS–AS染色体；
- 混合初始化；
- 完整解码；
- 遗传操作；
- NSGA-II多目标选择；
- N1–N6的基本修改含义。

这些内容可以作为原方法基础继续使用，但涉及实现行为的项目必须先通过A2一致性核验。“继承”不是允许跳过验证。

### B. 静态化后继承

- 符号表；
- 问题假设；
- 决策变量；
- 约束条件。

只保留静态内容，并增加新算法控制符号；动态扰动、重调度和稳定性内容不进入当前论文。

### C. 创新方法必须深化和重新定义

- 机器与AGV瓶颈指标；
- 工序贡献排序和跨资源Top-K区域；
- N1–N6在Top-K区域内的执行语义；
- 静态状态空间；
- `a=(K,N,b)`动作与合法动作掩码；
- 奖励、探索/利用、Q表生命周期；
- 真实解码预算及扣减；
- 新算法伪代码、输入输出、复杂度、小案例和消融差异表。

## 五、明确禁止越界

未经新的书面变更决定，不得把创新扩展到以下位置：

- 不改变问题类型、调度目标和约束；
- 不改变染色体结构；
- 不改变完整解码器行为；
- 不改变基础遗传操作和NSGA-II环境选择；
- 不新增动态订单、机器故障或AGV故障；
- 不新增代理模型、预测筛选、深度强化学习或其他额外模块；
- 不允许只对Top-K局部解码；
- 不允许不计费的内部真实解码；
- 不允许用正式测试集选择固定最佳配置或调参数。

## 七、当前冻结与待深化的区别

已经冻结的是：**研究范围、创新所在阶段、共同底座、禁止越界项和比较身份。**

尚未冻结的是：机器/AGV瓶颈公式、贡献排序、K和b具体取值、状态离散、奖励归一化及权重、ε策略、Q表细节、动作掩码、复杂度公式和小案例数值。这些属于创新方法深化研究，不允许借深化之名扩大创新范围。

本文件固定边界，不代表P03-13至P03-33已经完成，也不代表新方法有效。后续每一项定义必须落在本文件划定的创新阶段内，并接受A4原型检查和A5正式协议复核。
