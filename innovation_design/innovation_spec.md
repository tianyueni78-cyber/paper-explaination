# 创新算法规格（候选版）

## 1. 暂定名称

**面向多目标动态机器–AGV协同调度的事件–瓶颈感知、计算预算自适应 Q-learning 局部搜索方法**

英文工作名：**Budget-aware Q-learning Local Search for Dynamic Machine–AGV Scheduling**。

> 当前是待验证的增量创新，不提前宣称“首次”“精确”或“显著优于”。只有通过文献核验和实验后才冻结题目与表述。

## 2. 要解决的具体不足

原 QNSGA-II 使用 Q-learning 在 N1–N6 中选择单个规则邻域。它能够进行局部改进，但动作主要规定“使用哪个邻域”，没有系统地同时决定：

- 当前动态状态下应重点调整哪一类瓶颈区域；
- 局部搜索范围应多大；
- 在有限响应时间内应把多少计算预算投入本次搜索。

因此，本研究的问题定义为：

> 在问题、场景和总计算预算不变的条件下，能否利用事件、瓶颈与搜索状态，自适应选择合法局部区域和搜索强度，使算法在动态重调度时获得更高的单位时间收益？

## 3. 第一主张与次要观察

### 第一主张

在相同墙钟时间预算下，提高动态重调度的**质量–时间效率与响应能力**。

### 次要观察

- Pareto 解集质量是否提高；
- 不同随机种子下的结果是否更稳定；
- 停滞阶段能否更快恢复改进；
- 不同事件严重程度下是否会选择不同搜索强度。

本方案暂不把“收敛性证明”“更高多样性”或“局部最优保证”作为主张。

## 4. 必须保持一致的部分

为了把性能差异归因于新局部搜索，创新算法与冻结 baseline 必须共用：

| 层面 | 必须一致的内容 |
|---|---|
| 问题与场景 | 机器–AGV协同调度模型、动态事件类型和发生规则 |
| 数据 | 相同实例、参数、距离、加工时间、能耗和电池数据 |
| 表示 | 相同染色体及 OS、MS、AS、速度等片段的定义 |
| 解码 | 冻结后的同一个领域专用解码器；不另写“更有利”的解码逻辑 |
| 目标 | Makespan 与 TEC 的相同定义和计算方式 |
| 动态约束 | 已完成/执行中任务继承、故障资源禁用、AGV位置/电量/可用时间继承 |
| NSGA-II主体 | 初始化协议、选择、交叉、变异、非支配排序、拥挤度和精英保留 |
| 比较协议 | 相同实例、种子策略、运行次数、预算和评价指标 |

原解码器不是 NSGA-II 自带的通用解码器，而是论文/代码针对机器–AGV约束实现的领域解码逻辑。创新算法继续调用它：先读取其排程结果诊断瓶颈，修改染色体后再用同一解码器完整评价。

## 5. 必须改变的部分

### 5.1 状态诊断层

从已解码计划提取少量、可解释的状态：

- 动态事件类型及影响规模；
- 机器或 AGV 瓶颈类型；
- 搜索停滞程度；
- 剩余墙钟预算比例。

第一版只采用可直接计算的分箱特征，不训练额外预测模型。

### 5.2 合法区域生成层

围绕瓶颈及其强耦合工序生成候选局部区域：

- 小范围：瓶颈资源附近的少量工序；
- 中范围：瓶颈资源及直接前后继、关联运输任务；
- 暂不实现大范围，以控制复杂度和非法解风险。

区域生成必须遵守动态锁定边界，不得修改已完成或不可重调任务。

### 5.3 Q-learning 决策层

Q-learning 不再只选择 N1–N6，而从少量固定复合动作中选择：

> **区域类型/规模 + 合法邻域组合 + 本次时间配额**

第一版建议 4–6 个离散动作，避免状态–动作空间失控。原有 ε-greedy 和 Q 表更新框架原则上保留；这不是“新增贪心算法”。

### 5.4 预算管理层

预算分配不是随便决定，也不是先上预测模型，而是由以下量驱动：

- 总墙钟预算与剩余预算；
- 当前停滞程度；
- 事件影响规模和瓶颈类型；
- 各动作历史上的单位时间收益，由 Q 值逐步学习。

所有动作受硬时间上限约束；预算不足时只允许低成本动作。

### 5.5 奖励层

奖励同时反映质量与代价，具体归一化公式必须在探针实验后冻结：

`奖励 = 解/档案质量增量 ÷ 搜索耗时 − 非法解惩罚 − 超时惩罚`

不得直接把不同量纲的 Makespan、TEC 和秒数裸相加。

## 6. 第一版明确不做

- 不修改问题模型、数据、动态场景、目标函数或解码器；
- 不把 Q-learning 换成 PPO、DQN 等深度强化学习；
- 不加入需求预测或新数据；
- 不调用数学求解器进行所谓“精确修复”；
- 不一次扩展大量连续动作或大范围解锁；
- 不改变 NSGA-II 的选择、交叉、变异、排序和精英保留。

这些内容只有在第一版证据不足且有明确必要性时，才作为后续独立研究问题。

## 7. 算法流程与原算法接口

1. 使用 baseline 方式初始化并通过同一解码器评价种群。
2. NSGA-II 生成子代并进行第一次环境选择。
3. 从候选解的完整排程中提取事件、瓶颈、停滞和预算状态。
4. Q-learning 选择一个合法复合动作。
5. 区域生成器确定可解锁的小/中范围工序及关联机器、AGV任务。
6. 在分配的时间配额内执行既有或组合邻域搜索。
7. 使用同一 baseline 解码器完整解码并计算 Makespan、TEC。
8. 根据质量增量、耗时和合法性计算奖励并更新 Q 表。
9. 将局部搜索候选与当前种群合并，按 baseline 方法再次排序和筛选。
10. 动态事件发生后继承冻结状态，只优化合法未锁定区域。

## 8. 预期创新落点

优先落点：

1. **算法效率**：同等时间内得到更好的 Pareto 解集；
2. **动态响应能力**：根据事件影响与剩余时间调整搜索强度；
3. **运行稳定性**：减少高成本无效搜索和超时，但需统计验证。

解的目标质量可能随之提高，但不是不受预算约束的独立承诺。

## 9. 消融与公平比较

至少比较：

- B0：冻结的原 QNSGA-II；
- B1：随机选择区域与预算；
- B2：固定小范围局部搜索；
- B3：瓶颈感知区域，但不使用 Q-learning；
- B4：完整预算感知 Q-learning 版本。

主比较采用相同墙钟时间；补充报告相同解码/评价次数，以避免硬件和代码开销造成误导。

## 10. 仓库边界

- `Python-NEW` 只保存 baseline 复现、验证证据及其文档；
- 本目录目前只保存创新设计，不修改 baseline 代码；
- baseline 验收后，用其明确 commit/tag 建立独立创新工作区；
- 创新代码、配置和结果进入独立仓库，baseline 以固定版本作为依赖来源或复制起点；
- 禁止把创新修改反向混入 baseline。

## 11. 冻结条件

同时满足以下条件后才把候选方案写成正式论文创新点：

1. 完成针对性文献核验，未发现高度同构的方法组合；
2. `probe_protocol.md` 的快速探针达到 Go 条件；
3. baseline 已通过相关验证门并形成可引用的 commit/tag；
4. 状态、动作、奖励和预算规则均能用明确公式或伪代码复现；
5. 完整实验可以使用公平协议与 baseline 比较。
