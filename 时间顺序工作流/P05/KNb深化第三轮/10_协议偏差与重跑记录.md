# 协议偏差与重跑记录

## 结论

第三轮首次正式运行存在一项协议偏差：N1/N2的64次无解码机会抽样若为0，会被旧适配器错误地作为硬不可行掩码。该偏差已按批准设计修正，所有受影响的N和联合实验已经重跑；K、b及不含N的K×b单元不受影响。

## 根因

批准设计区分两件事：

- **硬掩码：** 只有结构上能证明动作不可行时才关闭；
- **机会强度：** 64次固定抽样用于描述N1/N2在区域内产生合法修改的频率。

旧实现把两者共用同一数值，导致“64次恰好没有命中”被解释成“动作不可能执行”。根因是数据语义混合，不是N1/N2邻域语义或冻结A0发生变化。

## 修正

N1/N2在OS长度至少3且区域含至少2个操作时保守保留；抽样率仍用于状态和日志，但不再决定硬掩码。新增自动测试强制模拟抽样率为0，并检查N1/N2仍在可行动作集合中。

## 重跑范围

| 实验 | 是否受影响 | 处理 |
|---|---|---|
| K单项 | 否，N固定为N3 | 保留`K-v1` |
| b单项 | 否，N固定为N3 | 保留`b-v1` |
| N单项 | 是 | 以`N-v7`替代`N-v6` |
| 完整规则/Q对照 | 是 | 以`Q-v2`替代`Q-v1` |
| 八组析因 | 含N的010/011/110/111受影响 | 整体重跑为`interaction-v2`，保证单一一致数据集 |
| 旧冒烟 | 是技术记录 | `smoke-v4`已完成最终复核 |

旧目录不删除，作为发现和修正过程的审计证据；当前性能结论只能引用上表指定的新版本。

## 修正后的证据变化

- N单项仍未通过：2/6实例正向，区间跨0，单位解码收益略负。
- 111相对000由旧的`+0.008889`降为`+0.002118`，只有3/6实例正向。
- 111相对固定K50由旧的`-0.008572`降为`-0.015343`，HV和单位解码收益区间均低于0。
- K×b的HV交互仍为正；K×N与三阶交互转为明确负值。

因此修正没有改变“不冻结第三轮机制”的总裁决，但使失败位置更明确：当前N联合方式是完整机制的主要拖累项。
