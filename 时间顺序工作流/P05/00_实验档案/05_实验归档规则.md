# P05实验归档规则

## 一轮实验的标准目录

```text
轮次名称/
├─ README.md
├─ 01_实验协议.md
├─ protocol.json
├─ scripts/
│  ├─ run_experiment.py
│  ├─ analyze.py
│  └─ test_*.py
├─ runs/
│  └─ run-id/
│     ├─ manifest.json
│     ├─ raw_results.jsonl.gz
│     └─ analysis.json
├─ 02_实验结论.md
└─ 03_验收记录.md
```

目录名称可按实验调整，但证据职责不能缺失。

## 每轮必须记录的内容

### 实验前

- 研究问题和可证伪假设；
- baseline、固定强对照和消融；
- 实例、种子、父解来源和数据分层；
- 动作、状态、预算和真实解码扣减；
- 主指标、辅助指标和统计单位；
- 超时、失败、零收益和缺失数据处理；
- 继续、停止或转向规则。

### 运行时

- Git提交、A0来源哈希、Python及依赖版本；
- 完整命令、开始与结束时间、硬件和进程设置；
- 全部参数、种子和随机流标识；
- 生成数、唯一候选数、真实解码数和接受数；
- 全部失败、超时和未完成记录；
- 原始输出，不只保存汇总均值。

### 实验后

- 结论先行；
- 逐实例、配对差值、效果大小和不确定性；
- HV、Makespan、TEC及单位真实解码结果；
- 支持、反证、替代解释和适用范围；
- “实验是否完成”和“机制是否有效”分别判断；
- 独立验收记录及具体证据链接。

## 状态更新规则

1. 只有计划，没有代码和运行数据：标记“仅设计”。
2. 运行超时或配对不全：标记“部分完成”，保留全部数据，不从部分结果作正式性能结论。
3. 实验按协议完成但结果为负：标记“实验完成；不支持当前实现”。
4. 局部探针为正但未经过强对照、保留数据或完整优化器：标记“有限支持”，不能写“创新有效”。
5. 后续证据修正旧解释时，不删除旧结论；在总账标明当前效力和替代结论。
6. 每轮结束后更新本实验档案，并在同一次提交中保存协议、代码、数据、结论和验收记录。
