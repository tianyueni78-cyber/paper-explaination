# 论文全流程时间顺序工作流（替代方案，待确认）

## 一、先说结论

现行管理方式的问题，不是任务数量不够，而是同时使用了三套验收轴：A1–A8、P01–P11、297项矩阵。同一成果被拆到多个阶段，导致“材料已经出现”被误当成“节点已经完成”，也无法明确回答当前到底做到哪一步。

建议改为一条严格的时间顺序链：**P01 → P02 →……→ P11**。P01–P11既是交付包，也是唯一的阶段节点。任何时刻只允许一个节点处于“进行中”；前一节点未通过，不开启后一节点。

其中，**静态A0 baseline冻结是第一个实质研究节点（P02）**。P01只负责锁定研究边界、输入材料和验收规则，不能开展创新设计或实验。

## 二、采用的专家组合

本工作流不是凭经验随意排列，而是组合使用以下Skill：

1. `academic-research-suite`：提供从研究问题、证据、实验到论文与复现包的端到端主流程。
2. `idea-evaluator`：在投入创新实现前审查研究想法的价值、可行性和致命缺陷。
3. `tech-paper-template`：把研究缺口、核心思想、挑战、方法模块和贡献组织成一致的论文逻辑。
4. `paper-writer`：只在证据和结果已经形成后进入正式写作，防止先写结论再补实验。
5. `pre-submission-reviewer`：在投稿前从逻辑、语言、格式和图表等方面独立验收。
6. `static-machine-agv-research`：约束本项目的静态机器–AGV边界、A0身份、TEC口径和创新隔离。

组合原则是：端到端流程负责排序，项目专用Skill负责领域边界，其余Skill分别在相应节点担任专项审查人。没有一个Skill单独决定全部工作流。

## 三、唯一有效的验收规则

### 3.1 状态规则

每个节点只能取以下状态之一：

- `未开始`：前序节点尚未通过；即使已有零散材料，也不能写“进行中”。
- `进行中`：当前唯一正在验收的节点。
- `通过`：本节点所有必交成果均已完成、核查并形成结论文档。
- `退回`：发现影响结论的问题，必须补做后重新验收。

不再使用完成百分比。未来节点提前产生的内容统一标记为“候选材料”，不计入节点进度。

### 3.2 单一归属规则

每项成果只能在一个节点首次交付和验收。后续节点可以引用、复核或因新证据申请重开，但不能与前序节点共同拥有同一项任务。

### 3.3 闸门规则

- 只有当前节点可以标记“进行中”。
- 当前节点未通过，下一节点保持“未开始”。
- 节点通过必须同时具备：必交文件、核验记录、未决事项清零或获批豁免、节点结论文档。
- 后续发现的问题若改变上游结论，必须重开对应上游节点；受影响的下游节点自动失效并重新验收。

### 3.4 结论先行规则

每个节点必须提交一份可直接阅读的中文结论文档，固定回答：

1. 本节点最终结论是什么？
2. 哪些内容已经固定，哪些明确不属于本节点？
3. 结论由哪些代码、数据、论文或测试支撑？
4. 是否存在未决事项或风险？
5. 为什么可以进入下一节点？

只有清单没有结论文档，不能验收通过。

### 3.5 阶段通过后的能力学习建议

每个节点通过时，除科研验收结论外，必须另给用户一段“能力学习建议”，回答：

1. 本阶段接触了哪些可迁移到就业场景的能力；
2. 在自然语言编码成为主要编码方式的前提下，哪些仍值得本人掌握；
3. 应掌握到什么深度：会描述、会审查、会调试，还是需要能手写；
4. 哪些机械操作可以交给AI，不建议投入大量时间死记；
5. 给出一个与本阶段成果直接相关的最小练习。

这属于学习与就业建议，不属于科学验收证据，不影响节点“通过/退回”的判定。
